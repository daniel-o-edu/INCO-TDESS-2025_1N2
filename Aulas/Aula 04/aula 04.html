Aula 04 - Fundamentos da Linguagem C Embarcada

Descrição: Estudo de sintaxe básica, tipos de dados, variáveis, operadores matemáticos/lógicos e boas práticas de código limpo em C.

01

Bloco 1 — Introdução ao C para Sistemas Embarcados

1.1. O Papel do Compilador e o Fluxo de Execução

Na programação de microcontroladores (como a plataforma Arduino), o código escrito no computador é chamado de sketch. Esse código é redigido em um dialeto baseado na linguagem C/C++ (frequentemente associado à linguagem de programação Wiring). No entanto, microcontroladores não conseguem ler texto diretamente; eles compreendem apenas níveis lógicos de tensão e instruções em formato binário.

O compilador é o utilitário de software responsável por traduzir o código-fonte legível por humanos para o código de máquina (arquivos binários contendo sequências de 0s e 1s).

  • Verify (Verificar): Analisa a sintaxe do programa para garantir que ele respeita rigorosamente as regras estruturais da linguagem C.
  • Upload (Carregar): Conclui o processo de compilação, transfere o arquivo binário gerado através do cabo USB e o grava permanentemente na memória do chip de controle do hardware.

1.2. A Estrutura Básica de um Sketch

Um programa para microcontrolador obrigatoriamente deve conter duas funções fundamentais pré-definidas para que possa compilar com sucesso:

void setup() {
 // Código executado apenas uma única vez
}

void loop() {
 // Código executado repetidamente em ciclo infinito
}
  • A Função setup(): Executada apenas uma única vez no momento em que a placa é ligada, quando o botão Reset é pressionado ou após a transferência de um novo código. Destina-se às configurações iniciais do sistema, como a definição dos pinos (pinMode), inicialização de taxas de transmissão seriais (Serial.begin) e acionamento inicial de periféricos.
  • A Função loop(): Entra em execução sequencial imediatamente após o término de setup(). Seu comportamento é o de um laço de repetição infinito (ciclo de amostragem), executando as linhas de cima para baixo e reiniciando ao atingir a chave de fechamento. É onde ocorrem as leituras contínuas de sensores, o processamento de lógica de controle e o acionamento dinâmico de atuadores.

1.3. Gerenciamento de Memória e Restrições de Hardware

Diferente de um computador pessoal, os microcontroladores operam sob severas limitações físicas de recursos computacionais:

  • 1. Memória Flash (Não Volátil): Destina-se ao armazenamento do código binário do programa (o sketch compilado). Os dados não são perdidos ao desligar. No ATmega328 (Arduino Uno), há 32 kB de Flash (2 KB para bootloader, restando 30 kB úteis). No ATmega2560 (Arduino Mega), há 128 kB de Flash (4 kB para bootloader).
  • 2. Memória SRAM (Volátil): Memória de trabalho para armazenar variáveis temporárias, pilhas de funções e dados de comunicação. O ATmega328 possui somente 2 kB (2.000 bytes) de SRAM.
  • 3. Memória EEPROM (Não Volátil e Gravável): Utilizada para persistência de dados de calibração que devem sobreviver à falta de energia elétrica, mas que precisam ser alterados eventualmente por software.
Consequência Crítica: Se a SRAM se esgotar, o Arduino não emite alertas; ele simplesmente trava ou reinicia sem aviso prévio. Para economizar SRAM, podemos armazenar dados imutáveis na Flash usando o modificador PROGMEM (biblioteca <avr/pgmspace.h>).

1.4. Boas Práticas Iniciais: Código Limpo Embarcado

Desenvolver código limpo (clean code) em hardware de recursos restritos é essencial para a manutenção e estabilidade do projeto:

  • Nomenclatura de Variáveis (Convenção CamelCase): Nomes descritivos, sem espaços ou caracteres especiais. Iniciam com letras minúsculas e as palavras seguintes com maiúsculas (ex: ledPin ou tempoEsperaAlerta).
  • Indentação e Espaços em Branco: O compilador ignora recuos, quebras de linha ou espaços, que servem para a leitura humana. Organize o código com chaves alinhadas para delimitar os escopos de forma legível.
  • Comentários Descritivos: Explicam o funcionamento e a intenção da lógica. Em C, utilizamos:
    • // para comentários de linha única.
    • /* e */ para comentários multilinha ou blocos de código.

Bloco 2 — Tipos de Dados e Variáveis

2.1. Tipos Primitivos na Arquitetura AVR (8 bits)

Uma variável é uma região nomeada da memória SRAM onde podemos armazenar informações durante o processamento. Em C, é obrigatório declarar o tipo exato de dado:

Tipo de Dado Tamanho SRAM Faixa de Valores Aplicação Recomendada
boolean / bool 1 byte true (1) ou false (0) Flags de estado (ex: ledLigado = true).
char 1 byte -128 a 127 Caracteres ASCII em aspas simples (ex: 'A').
byte 1 byte 0 a 255 Controle de pinos físicos e comunicação serial.
int 2 bytes (16 bits) -32.768 a 32.767 Leituras de ADC (0 a 1023), cálculos e contadores pequenos.
unsigned int 2 bytes (16 bits) 0 a 65.535 Contadores estritamente positivos de até 16 bits.
long 4 bytes (32 bits) -2.147.483.648 a 2.147.483.647 Cálculos matemáticos grandes.
unsigned long 4 bytes (32 bits) 0 a 4.294.967.295 Medições de tempo longas via função millis().
float 4 bytes (32 bits) ±3.4028235 × 1038 Números reais/ponto flutuante (cálculos de engenharia/física).
double 4 bytes (32 bits) O mesmo que o float No Arduino Uno, não possui precisão dupla de 8 bytes.

2.2. Modificadores de Tipo

Os modificadores alteram a forma como o compilador reserva espaço e gerencia o bit de sinal:

  • signed: Modo padrão. Mantém o bit mais significativo para representação do sinal algébrico (positivos e negativos).
  • unsigned: Elimina o bit de sinal, permitindo apenas números positivos e zero, dobrando a capacidade positiva (ex: char de -128 a 127 vira unsigned char de 0 a 255).
  • short: Garante tamanho fixo de 16 bits.
  • long: Expande variáveis inteiras para 32 bits.
Regra de Ouro para Recursos Restritos: Escolher sempre o menor tipo de dado suficiente para a tarefa é um princípio de otimização crucial.
Exemplo: Armazenar o número de uma porta física em int consome 2 bytes; usando byte, consome-se apenas 1 byte (economizando 50%).

2.3. Escopo de Variáveis: Locais versus Globais

O local de declaração define a visibilidade e o tempo de existência da variável na memória:

int pinoSensor = A0; // VARIÁVEL GLOBAL: Visível em todo o código.

void loop() {
 int leituraLocal = analogRead(pinoSensor); // VARIÁVEL LOCAL: Existe apenas no ciclo do loop().
 static int contadorBipes = 0; // LOCAL ESTÁTICA: Visível apenas no loop(), mas preserva valor.
 contadorBipes++;
}
  • 1. Variáveis Globais: Declaradas no topo. Permanecem na SRAM continuamente. O uso massivo aumenta desnecessariamente o consumo de RAM e dificulta o diagnóstico de erros.
  • 2. Variáveis Locais: Declaradas dentro de blocos. Criadas na execução do bloco e destruídas ao término, liberando memória.
  • 3. Variáveis Locais Estáticas (static): Visíveis apenas na função, mas mantêm o valor acumulado entre chamadas sem precisar virar global.

2.4. Diretiva #define versus Qualificador const

Para associar nomes a pinos ou constantes imutáveis, existem dois caminhos em C:

A Diretiva #define

  • Instrução para o pré-processador antes da compilação. Substitui o texto pelo valor literal.
  • Sintaxe: #define ledPin 13 (Sem sinal = e sem ponto e vírgula ;).
  • Vantagem: Não consome nenhum byte da SRAM, pois o valor é gravado direto na Flash.

O Qualificador const

  • Declara uma variável convencional marcada como somente leitura. Valor atribuído obrigatoriamente na declaração.
  • Sintaxe: const byte ledPin = 13;
  • Vantagem: Respeita regras de escopo e tipagem estrita em C, facilitando a depuração.

Bloco 3 — Operadores Matemáticos, Lógicos, de Atribuição e Precedência

3.1. Operadores Aritméticos e Divisões

Operadores aritméticos realizam cálculos sobre valores numéricos: + (Adição), - (Subtração), * (Multiplicação), / (Divisão) e % (Módulo/Resto - apenas inteiros).

A Armadilha da Divisão Inteira: Em C, se ambos os operandos forem inteiros, a divisão será inteira, descartando a parte fracionária. 
int resultado1 = 5 / 2; 
// resultado1 recebe 2 (descarte decimal)

float resultado2 = 5 / 2; 
// resultado2 recebe 2.0 (a divisão inteira ocorre ANTES da atribuição!)

float resultado3 = 5.0 / 2.0; 
// resultado3 recebe 2.5 (ao menos um valor forçado como float)

3.2. Operadores Relacionais e Lógicos

Comparam valores/expressões e retornam um valor booleano: 1 (verdadeiro) ou 0 (falso).

Operadores Relacionais (Comparação):

  • == (Igual a — cuidado para não confundir com o operador de atribuição =)
  • != (Diferente de)
  • > (Maior que) / < (Menor que)
  • >= (Maior ou igual a) / <= (Menor ou igual a)

Operadores Lógicos (Conexão de Condições):

  • && (Operador E / AND): Retorna Verdadeiro (1) apenas se TODAS as condições forem verdadeiras.
  • || (Operador OU / OR): Retorna Verdadeiro (1) se pelo menos uma condição for verdadeira.
  • ! (Operador NEGAÇÃO / NOT): Inverte o valor lógico da expressão.

3.3. Incremento, Decremento e Atribuições Compactas

Atribuição Composta:

Substituem a repetição da variável de destino: x += y (x = x + y), x -= y, x *= y, x /= y, x %= y.

Atenção para a Precedência Oculta: x *= y - 10; equivale a x = x * (y - 10); (o operador atua sobre o resultado total da direita).

Pré e Pós-Incremento/Decremento:

int x = 10;
int y = x++; // Pós-incremento: y recebe 10 (valor original) e x passa a ser 11.

int a = 10;
int b = ++a; // Pré-incremento: a passa a 11 e b recebe 11 (valor já incrementado).

3.4. Tabela de Precedência de Operadores

Ordem fixa de execução do compilador (do maior para o menor nível de prioridade):

Nível Operadores Descrição
1 ++ -- () [] Pré-incremento/decremento, parênteses, elementos de array
2 ++ -- ! Pós-incremento/decremento, negação lógica
3 * / % Multiplicação, divisão, módulo
4 + - Adição, subtração
5 << >> Deslocadores de bits
6 < <= > >= Relacionais de magnitude
7 == != Relacionais de igualdade/diferença
8 && Operador lógico E
9 || Operador lógico OU
10 = += -= *= /= %= Atribuição simples e composta

Resumo das Boas Práticas da Aula

  • 1. Sempre prefira o tipo de dado de menor tamanho possível para economizar a preciosa memória SRAM do microcontrolador (ex: use byte para pinos).
  • 2. Declare variáveis com escopo local sempre que possível para que a memória SRAM seja liberada ao fim das funções.
  • 3. Utilize #define para associar nomes fáceis a pinos físicos do circuito sem desperdiçar memória RAM de variáveis.
  • 4. Cuidado redobrado com a divisão inteira e garanta que ao menos um elemento seja representado com ponto decimal (como .0) quando necessitar de resultados com casas fracionárias.

Bloco 4 — Laboratório Prático e Revisão de Código Limpo

4.1. Análise de Código Legado e Refatoração Guiada

Objetivo Pedagógico: Desenvolver a capacidade crítica de identificação de más práticas de programação embarcada, compreendendo os impactos diretos do uso inadequado de memória no comportamento físico do microcontrolador (ATmega328P).

4.1.1. Código Legado Ineficiente

int pinoLeitura = A0; // Pino do sensor analógico
int pinoLed = 13; // Pino do LED de alerta
int valorLido = 0; // Leitura bruta do ADC
float tensao = 0; // Tensão calculada em Volts

void setup() {
 Serial.begin(9600);
 pinMode(pinoLed, OUTPUT);
}

void loop() {
 valorLido = analogRead(pinoLeitura);
 tensao = valorLido / 1023 * 5; // Cálculo da tensão equivalente
 if(tensao > 2.5) {
 digitalWrite(pinoLed, HIGH);
 } else {
 digitalWrite(pinoLed, LOW);
 }
 delay(1000);
}

Atividade 4.1.2:

Identificar cinco falhas de boas práticas/otimização e reescrever o código aplicando os princípios de código limpo embarcado.

4.2. Desafio Prático: Refatoração de Sistema Térmico

Contexto: Módulo de monitoramento de sobreaquecimento (ATmega328P). Lê sensor analógico (A1), aciona cooler (pino 8), pisca alarme (pino 9) acima de 45°C e contabiliza acionamentos. O código legado lê 0°C constantemente, trava o temporizador e esgota a RAM.

Código Legado Ineficiente:

int PINO_SENSOR = A1;
int PINO_COOLER = 8;
int PINO_ALARME = 9;
int leituraBruta = 0;
float temperatura = 0;
int contadorAlertas = 0;
int tempoAnterior = 0;

void setup() {
 Serial.begin(9600);
 pinMode(PINO_COOLER, OUTPUT);
 pinMode(PINO_ALARME, OUTPUT);
}

4.2. Desafio Prático: Código Legado (Continuação)

void loop() {
 leituraBruta = analogRead(PINO_SENSOR);
 // Conversão da leitura do ADC (0 a 1023) para graus Celsius (0 a 100°C)
 temperatura = (leituraBruta / 1023) * 100;

 if (temperatura > 45) {
 digitalWrite(PINO_COOLER, HIGH);
 // Incrementa contagem de alertas
 contadorAlertas = contadorAlertas + 1;

 // Pisca o alarme a cada 500 ms usando millis()
 if (millis() - tempoAnterior > 500) {
 digitalWrite(PINO_ALARME, HIGH);
 tempoAnterior = millis();
 }
 } else {
 digitalWrite(PINO_COOLER, LOW);
 digitalWrite(PINO_ALARME, LOW);
 }
}

4.2.2. Atividade em 3 Etapas

  • 1. Análise Crítica e Diagnóstico: Identificar e explicar 5 falhas de programação no código legado (tipos de dados, escopo, matemática, estouro de variáveis e código limpo).
  • 2. Cálculo de Consumo de Memória SRAM: Calcular os bytes de SRAM alocados no legado e determinar quantos bytes são salvos após a refatoração.
  • 3. Refatoração do Código Fonte: Reescrever o sketch aplicando:
    • Substituição de pinos fixos por #define ou const.
    • Escolha dos menores tipos primitivos adequados (byte, unsigned long, etc.).
    • Ajuste de escopo (variáveis locais e static).
    • Correção da armadilha da divisão inteira.
    • Uso de operadores compactos de incremento/atribuição.
    • Convenção CamelCase e comentários legíveis.
